## 1. Enumerations (Shared)

### 1.1 Source Type

| Value | Description |
|-------|-------------|
| `weather_api` | Structured weather API (e.g. Open-Meteo) |
| `rss` | Public RSS feed |
| `website` | Allowlist website scraper |
| `social` | API-compliant social media post |
| `simulated_social` | Controlled/simulated social feed (hackathon fallback — clearly labelled) |
| `government_dataset` | Batch-loaded government/public dataset |
| `citizen` | Citizen web-form submission |
| `synthetic` | Programmatically generated test record |

### 1.2 Event Category

| Value | Notes |
|-------|-------|
| `rainfall` | General / light rainfall |
| `heavy_rainfall` | Heavy or very heavy rainfall |
| `flood` | Surface flooding, flash flood |
| `thunderstorm` | Thunderstorm activity |
| `lightning` | Lightning strike or strike warning |
| `heatwave` | Extreme heat event |
| `fog` | Dense fog advisory |
| `dust_storm` | Dust / sand storm |
| `strong_wind` | Strong or gale-force winds |
| `hailstorm` | Hailstorm |
| `cyclone` | Cyclonic system |
| `other` | Confirmed weather event, unclassified |

> **Change control:** New categories require architect approval. Do NOT add
> categories casually during the five-day MVP.

### 1.3 Severity

| Value | Meaning |
|-------|---------|
| `low` | Minor, advisory-level |
| `moderate` | Noteworthy, requires awareness |
| `high` | Significant impact expected |
| `extreme` | Life/property-threatening |

### 1.4 Verification Status

| Value | Set By |
|-------|--------|
| `pending` | System default on ingestion |
| `verified` | Admin manual action |
| `needs_review` | Reserved for future use (no current action sets this) |
| `suspicious` | Low credibility / contradicted |
| `duplicate` | Admin or ML identified as duplicate |

## 2. Canonical Weather Event — JSON Schema

This is the **single shared structure** that every source adapter must produce.
All downstream Spark, ML, PostgreSQL writer, and API components consume this
structure exclusively.

```json
{
  "event_id":              "<uuid-v4>",
  "source_id":             "<string>",

  "source_type":           "<source_type enum>",
  "source_name":           "<string>",
  "source_url":            "<string | null>",
  "source_trust_score":    "<float 0.0–1.0 | null>",

  "timestamp":             "<ISO 8601 UTC>",
  "ingestion_timestamp":   "<ISO 8601 UTC>",

  "location": {
    "latitude":  "<float | null>",
    "longitude": "<float | null>",
    "city":      "<string | null>",
    "district":  "<string | null>",
    "state":     "<string | null>",
    "country":   "<string, default 'India'>"
  },

  "event": {
    "category":    "<event_category enum>",
    "severity":    "<severity enum | null>",

  },

    "hashtags":   ["<string>"],
    "author_id":  "<string | null>",

  },
```

## 3. Field Reference Table

### 3.1 Root Fields

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `event_id` | uuid-v4 string | ✅ YES | Generated by source adapter. Globally unique. |
| `source_id` | string | ✅ YES | Adapter-assigned identifier for the originating source record. |
| `source_type` | enum | ✅ YES | See §1.1 |
| `source_name` | string | ✅ YES | Human-readable name, e.g. `"Open-Meteo"`, `"IndiaTV RSS"` |
| `source_url` | string | ❌ optional | Originating URL if applicable |
| `source_trust_score` | float 0–1 | ❌ optional | Pre-computed source-level trust; null if not yet scored |
| `timestamp` | ISO 8601 UTC | ✅ YES | Event occurrence time. Must include timezone offset or `Z`. |
| `ingestion_timestamp` | ISO 8601 UTC | ✅ YES | Time adapter created this record. Set by adapter. |

### 3.2 Location Fields

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `location.latitude` | float −90 to 90 | ❌ optional | Decimal degrees (WGS-84) |
| `location.longitude` | float −180 to 180 | ❌ optional | Decimal degrees (WGS-84) |
| `location.city` | string | ❌ optional | City name, e.g. `"Mumbai"` |
| `location.district` | string | ❌ optional | District name |
| `location.state` | string | ❌ optional | State name, e.g. `"Maharashtra"` |
| `location.country` | string | ✅ YES | Default: `"India"` |

> **Location validation rule (precise):**
>
> - `latitude` and `longitude` MUST appear **together or not at all**.
>   If either is present without the other, the record is REJECT-ed.
> - If neither `latitude`/`longitude` nor `city` is present, the record is REJECT-ed.
> - `city` alone (without coordinates) is acceptable.
> - `latitude` + `longitude` together (without city) is acceptable.
> - All four location fields are optional at the schema level, but the
>   Spark validation rule above enforces the minimum-population requirement.

### 3.3 Event Fields

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `event.category` | enum | ✅ YES | See §1.2 |
| `event.severity` | enum | ❌ optional | See §1.3; null if not determinable at ingestion |
| `event.description` | string | ❌ optional | Free text; max 2000 chars |

### 3.4 Social Metadata Fields

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `social_metadata.hashtags` | string[] | ❌ optional | Empty array `[]` if none |
| `social_metadata.author_id` | string | ❌ optional | Anonymised identifier |
| `social_metadata.platform` | string | ❌ optional | e.g. `"twitter"`, `"simulated"` |

### 3.5 Media Fields

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `media.photos` | string[] | ❌ optional | URLs to stored images; empty array `[]` if none |
| `media.videos` | string[] | ❌ optional | URLs to stored videos; empty array `[]` if none |

### 3.6 AI Fields (populated by ML modules, empty at ingestion)

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `ai.classified_category` | enum | ❌ optional | ML-assigned category; may differ from adapter-assigned |

## 4. Timestamp Format

All timestamps MUST use **ISO 8601 with UTC offset**.

```
YYYY-MM-DDTHH:MM:SS.sssZ
```

Examples:
```
2026-08-31T14:30:00.000Z        ✅ valid
2026-08-31T20:00:00.000+05:30   ✅ valid
2026-08-31 14:30:00             ❌ invalid (space separator, no tz)
1725110400                      ❌ invalid (Unix timestamp not allowed)
```

Adapters MUST normalise all source timestamps to UTC before producing
the canonical event.

## 6. PostgreSQL / PostGIS Table Structure

> **JSON → PostgreSQL field mapping note:** The Canonical Weather Event (§2)
> uses nested objects (`location.latitude`, `event.category`, etc.) while the
> PostgreSQL table uses flat columns (`latitude`, `event_category`, etc.).
> The PostgreSQL writer must flatten nested fields. Key renames:
>
> | JSON path | PostgreSQL column |
> |-----------|------------------|
> | `location.latitude` | `latitude` |
> | `location.longitude` | `longitude` |
> | `location.city` | `city` |
> | `location.district` | `district` |
> | `location.state` | `state` |
> | `location.country` | `country` |
> | `event.category` | `event_category` |
> | `event.severity` | `severity` |
> | `event.description` | `description` |
> | `social_metadata.hashtags` | `hashtags` |
> | `social_metadata.author_id` | `author_id` |
> | `social_metadata.platform` | `platform` |
> | `media.photos` | `photo_urls` |
> | `media.videos` | `video_urls` |
> | `ai.classified_category` | `classified_category` |
> | `ai.classification_confidence` | `classification_confidence` |
> | `ai.duplicate_score` | `duplicate_score` |
> | `ai.credibility_score` | `credibility_score` |
> | `ai.credibility_reasons` | `credibility_reasons` |
> | `ai.cluster_id` | `cluster_id` |
> | `verification.status` | `verification_status` |
> | `verification.verified_by` | `verified_by` |
> | `verification.verification_timestamp` | `verification_timestamp` |
> | `timestamp` | `event_timestamp` |
> | `ingestion_timestamp` | `ingestion_timestamp` (same) |
> | — | `created_at` (auto-set by DB) |
> | — | `updated_at` (auto-set by trigger) |

### 6.1 `events` (primary table)

```sql
CREATE TABLE events (
    -- Identity
    event_id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    source_id           TEXT NOT NULL,

    -- Source
    source_type         TEXT NOT NULL
                            CHECK (source_type IN (
                                'weather_api','rss','website','social',
                                'simulated_social','government_dataset',
                                'citizen','synthetic'
                            )),
    source_name         TEXT NOT NULL,
    source_url          TEXT,
    source_trust_score  NUMERIC(4,3) CHECK (source_trust_score BETWEEN 0 AND 1),

    -- Time
    event_timestamp     TIMESTAMPTZ NOT NULL,
    ingestion_timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    -- Location (scalar)
    latitude            NUMERIC(9,6) CHECK (latitude  BETWEEN -90  AND 90),
    longitude           NUMERIC(10,6) CHECK (longitude BETWEEN -180 AND 180),
    city                TEXT,
    district            TEXT,
    state               TEXT,
    country             TEXT NOT NULL DEFAULT 'India',

    -- Location (spatial index target)
    geom                GEOMETRY(Point, 4326),

    -- Event
    event_category      TEXT NOT NULL
                            CHECK (event_category IN (
                                'rainfall','heavy_rainfall','flood',
                                'thunderstorm','lightning','heatwave',
                                'fog','dust_storm','strong_wind',
                                'hailstorm','cyclone','other'
                            )),
    severity            TEXT CHECK (severity IN ('low','moderate','high','extreme')),
    description         TEXT CHECK (char_length(description) <= 2000),

    -- Social metadata
    hashtags            TEXT[],
    author_id           TEXT,
    platform            TEXT,

    -- Media
    photo_urls          TEXT[],
    video_urls          TEXT[],

    -- AI
    classified_category       TEXT CHECK (classified_category IN (
                                'rainfall','heavy_rainfall','flood',
                                'thunderstorm','lightning','heatwave',
                                'fog','dust_storm','strong_wind',
                                'hailstorm','cyclone','other'
                              )),
    classification_confidence NUMERIC(4,3) CHECK (classification_confidence BETWEEN 0 AND 1),
    duplicate_score           NUMERIC(4,3) CHECK (duplicate_score BETWEEN 0 AND 1),
    credibility_score         NUMERIC(4,3) CHECK (credibility_score BETWEEN 0 AND 1),
    credibility_reasons       TEXT[],
    -- Note: cluster_id references event_clusters, which itself references back
    -- to events via representative_id. This is intentionally NOT a circular FK:
    -- cluster_id has a FK to event_clusters, but representative_id has NO FK
    -- to events. See §7 for explanation.
    cluster_id                UUID REFERENCES event_clusters(cluster_id) ON DELETE SET NULL,

    -- Verification
    verification_status     TEXT NOT NULL DEFAULT 'pending'
                                CHECK (verification_status IN (
                                    'pending','verified','needs_review',
                                    'suspicious','duplicate'
                                )),
    verified_by             TEXT,
    verification_timestamp  TIMESTAMPTZ,

    -- Audit
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 6.2 `event_clusters`

```sql
CREATE TABLE event_clusters (
    cluster_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    -- Note: representative_id intentionally has NO FK to events(event_id)
    -- to avoid circular dependency (events→event_clusters→events).
    -- The writer sets this on cluster creation; referential integrity is
    -- enforced at the application level.
    representative_id   UUID,                       -- event_id of canonical member
    event_category      TEXT NOT NULL,
    city                TEXT,
    state               TEXT,
    centroid_geom       GEOMETRY(Point, 4326),
    member_count        INTEGER NOT NULL DEFAULT 1,
    first_event_at      TIMESTAMPTZ NOT NULL,
    last_event_at       TIMESTAMPTZ NOT NULL,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 6.3 `set_updated_at` trigger (applies to events, event_clusters, sources)

```sql
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_events_updated_at
    BEFORE UPDATE ON events
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();

CREATE TRIGGER trg_event_clusters_updated_at
    BEFORE UPDATE ON event_clusters
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();

CREATE TRIGGER trg_sources_updated_at
    BEFORE UPDATE ON sources
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

## 9. PostGIS Geometry Definition

- CRS: **EPSG:4326** (WGS-84 geographic, decimal degrees)
- Type: `GEOMETRY(Point, 4326)` — stores (longitude, latitude) as a 2D point
- Populated from `latitude` / `longitude` scalar columns via trigger or writer

```sql
-- PostGIS must be enabled first:
CREATE EXTENSION IF NOT EXISTS postgis;

-- Trigger to auto-populate geom from lat/lon on insert/update:
CREATE OR REPLACE FUNCTION sync_geom()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.latitude IS NOT NULL AND NEW.longitude IS NOT NULL THEN
        NEW.geom := ST_SetSRID(ST_MakePoint(NEW.longitude, NEW.latitude), 4326);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_sync_geom
    BEFORE INSERT OR UPDATE OF latitude, longitude
    ON events
    FOR EACH ROW EXECUTE FUNCTION sync_geom();
```

## 10. Parquet Schema (Historical / Data Lake)

Written to `/data/processed/weather_events/` partitioned by `year`, `month`, `day`
derived from `event_timestamp`.

```
weather_events.parquet
├── event_id              STRING
├── source_id             STRING
├── source_type           STRING
├── source_name           STRING
├── source_url            STRING (nullable)
├── source_trust_score    DOUBLE (nullable)
├── event_timestamp       TIMESTAMP (UTC)
├── ingestion_timestamp   TIMESTAMP (UTC)
├── latitude              DOUBLE (nullable)
├── longitude             DOUBLE (nullable)
├── city                  STRING (nullable)
├── district              STRING (nullable)
├── state                 STRING (nullable)
├── country               STRING
├── event_category        STRING
├── severity              STRING (nullable)
├── description           STRING (nullable)
├── hashtags              ARRAY<STRING>
├── author_id             STRING (nullable)
├── platform              STRING (nullable)
├── photo_urls            ARRAY<STRING>
├── video_urls            ARRAY<STRING>
├── classified_category         STRING (nullable)
├── classification_confidence   DOUBLE (nullable)
├── duplicate_score             DOUBLE (nullable)
├── credibility_score           DOUBLE (nullable)
├── credibility_reasons         ARRAY<STRING>
├── cluster_id                  STRING (nullable)
├── verification_status         STRING
├── verified_by                 STRING (nullable)
├── verification_timestamp      TIMESTAMP (nullable)
├── year                    INT     (partition key — derived from event_timestamp)
├── month                   INT     (partition key — derived from event_timestamp)
└── day                     INT     (partition key — derived from event_timestamp)
```

> **Partitioning note:** `year`, `month`, `day` are derived from `event_timestamp`
> (the event occurrence time, not ingestion time). Spark writes using
> `withColumn("year", year("event_timestamp"))` etc. The partition path format
> uses Hive-style partitioning: `year=YYYY/month=MM/day=DD`.

Partition path example:
```
/data/processed/weather_events/year=2026/month=08/day=31/part-00000.parquet
```

## 11. Field Validation Rules (Spark Layer)

Spark validates each incoming canonical event against these rules.
Records that fail a **REJECT** rule are written to a dead-letter topic / log.
Records that fail a **WARN** rule are passed through with a flag.

| Field | Rule | On Failure |
|-------|------|-----------|
| `event_id` | Must be valid UUID v4, non-null | REJECT |
| `source_type` | Must be in §1.1 enum | REJECT |
| `source_name` | Non-null, non-empty string | REJECT |
| `event.category` | Must be in §1.2 enum | REJECT |
| `timestamp` | Valid ISO 8601 with timezone; must not be more than 5 minutes in the future (clock-skew tolerance); must not be before `2000-01-01T00:00:00Z` | REJECT |
| `ingestion_timestamp` | Valid ISO 8601 with timezone | REJECT |
| `location.country` | Non-null, non-empty string | REJECT |
| `location.latitude` | If present: must be between −90 and 90 (inclusive) | REJECT |
| `location.longitude` | If present: must be between −180 and 180 (inclusive) | REJECT |
| `location.latitude` ↔ `location.longitude` | If either is present, the other MUST also be present (coordinates are paired) | REJECT |
| `location` minimum | At least one of: (`latitude` + `longitude` together) **or** `city` must be present | REJECT |
| `event.description` | ≤ 2000 characters if present | WARN + truncate |
| `source_trust_score` | 0.0–1.0 if present | WARN + nullify |
| `event.severity` | Must be in §1.3 enum if present | WARN + nullify |
| `verification.status` | Default to `"pending"` if absent | AUTO-FIX |
| `source_type = synthetic` | Must have `source_name` containing `"synthetic"` | WARN |
| `source_type = simulated_social` | Must have `platform = "simulated"` | WARN |

## 12. How Each Source Produces a Canonical Event

Every source adapter is responsible for filling this mapping:

| Field | Weather API | RSS | Website | Social | Govt Dataset | Citizen | Synthetic |
|-------|------------|-----|---------|--------|-------------|---------|-----------|
| `event_id` | `uuid4()` | `uuid4()` | `uuid4()` | `uuid4()` | `uuid4()` | `uuid4()` | `uuid4()` |
| `source_type` | `weather_api` | `rss` | `website` | `social` / `simulated_social` | `government_dataset` | `citizen` | `synthetic` |
| `source_name` | `"Open-Meteo"` | feed title | site name | platform name | dataset filename | `"citizen_form"` | `"synthetic_gen"` |
| `timestamp` | API observation time | `<pubDate>` | extracted or now | post time | record timestamp | form submission time | generated |
| `location.latitude` | API coords | extracted from text | extracted from text | from post metadata | from dataset | from GPS/form | generated |
| `event.category` | inferred from conditions | extracted by NLP | extracted by NLP | extracted by NLP | from dataset field | from form dropdown | generated |
| `event.description` | constructed from fields | item description | scraped text | post text | from dataset | form description field | generated |
| `ai.*` | all null | all null | all null | all null | all null | all null | all null |
| `verification.status` | `"pending"` | `"pending"` | `"pending"` | `"pending"` | `"pending"` | `"pending"` | `"pending"` |

> `ai.*` fields are **always null at ingestion**. They are populated exclusively
> by ML modules inside the Spark processing job.

## 16. Dead-Letter Path

Records that fail REJECT rules are written to the **filesystem only** (no Kafka DLQ topic in MVP).

Path pattern:
```
/data/logs/dead_letter/YYYY-MM-DD/<source_type>_failures.jsonl
```

One file per `source_type` per calendar day (UTC). Each line is a JSON object:
```json
{
  "failed_at": "<ISO 8601 UTC>",
  "source_adapter": "<string>",
  "failure_reasons": ["<string>"],
  "original_record": { "...": "..." }
}
```

> This matches the dead-letter mechanism defined in `01_ARCHITECTURE.md §10`.
> A Kafka DLQ topic (`weather.dead_letter`) is deferred to a future version.

## 17. Complete Initialization SQL Order

The following order MUST be followed for a clean PostgreSQL deployment.
All SQL runs inside a single init script executed at container first start.

```sql
-- ============================================================
-- STEP 1: Extensions (must come before any table or function)
-- ============================================================
CREATE EXTENSION IF NOT EXISTS pgcrypto;     -- gen_random_uuid()
CREATE EXTENSION IF NOT EXISTS postgis;       -- GEOMETRY types, ST_* functions

-- ============================================================
-- STEP 2: Helper functions
-- ============================================================
CREATE OR REPLACE FUNCTION sync_geom()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.latitude IS NOT NULL AND NEW.longitude IS NOT NULL THEN
        NEW.geom := ST_SetSRID(ST_MakePoint(NEW.longitude, NEW.latitude), 4326);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- ============================================================
-- STEP 3: Tables (in dependency order)
-- ============================================================
-- 3a. event_clusters (no FK dependencies)
CREATE TABLE event_clusters (
    cluster_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    representative_id   UUID,
    event_category      TEXT NOT NULL,
    city                TEXT,
    state               TEXT,
    centroid_geom       GEOMETRY(Point, 4326),
    member_count        INTEGER NOT NULL DEFAULT 1,
    first_event_at      TIMESTAMPTZ NOT NULL,
    last_event_at       TIMESTAMPTZ NOT NULL,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3b. events (FK → event_clusters)
CREATE TABLE events (
    event_id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    source_id           TEXT NOT NULL,
    source_type         TEXT NOT NULL
                            CHECK (source_type IN (
                                'weather_api','rss','website','social',
                                'simulated_social','government_dataset',
                                'citizen','synthetic'
                            )),
    source_name         TEXT NOT NULL,
    source_url          TEXT,
    source_trust_score  NUMERIC(4,3) CHECK (source_trust_score BETWEEN 0 AND 1),
    event_timestamp     TIMESTAMPTZ NOT NULL,
    ingestion_timestamp TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    latitude            NUMERIC(9,6) CHECK (latitude  BETWEEN -90  AND 90),
    longitude           NUMERIC(10,6) CHECK (longitude BETWEEN -180 AND 180),
    city                TEXT,
    district            TEXT,
    state               TEXT,
    country             TEXT NOT NULL DEFAULT 'India',
    geom                GEOMETRY(Point, 4326),
    event_category      TEXT NOT NULL
                            CHECK (event_category IN (
                                'rainfall','heavy_rainfall','flood',
                                'thunderstorm','lightning','heatwave',
                                'fog','dust_storm','strong_wind',
                                'hailstorm','cyclone','other'
                            )),
    severity            TEXT CHECK (severity IN ('low','moderate','high','extreme')),
    description         TEXT CHECK (char_length(description) <= 2000),
    hashtags            TEXT[],
    author_id           TEXT,
    platform            TEXT,
    photo_urls          TEXT[],
    video_urls          TEXT[],
    classified_category       TEXT CHECK (classified_category IN (
                                'rainfall','heavy_rainfall','flood',
                                'thunderstorm','lightning','heatwave',
                                'fog','dust_storm','strong_wind',
                                'hailstorm','cyclone','other'
                              )),
    classification_confidence NUMERIC(4,3) CHECK (classification_confidence BETWEEN 0 AND 1),
    duplicate_score           NUMERIC(4,3) CHECK (duplicate_score BETWEEN 0 AND 1),
    credibility_score         NUMERIC(4,3) CHECK (credibility_score BETWEEN 0 AND 1),
    credibility_reasons       TEXT[],
    cluster_id                UUID REFERENCES event_clusters(cluster_id) ON DELETE SET NULL,
    verification_status     TEXT NOT NULL DEFAULT 'pending'
                                CHECK (verification_status IN (
                                    'pending','verified','needs_review',
                                    'suspicious','duplicate'
                                )),
    verified_by             TEXT,
    verification_timestamp  TIMESTAMPTZ,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3c. sources (no FK dependencies)
CREATE TABLE sources (
    source_name         TEXT PRIMARY KEY,
    source_type         TEXT NOT NULL,
    base_url            TEXT,
    trust_score         NUMERIC(4,3) NOT NULL DEFAULT 0.5
                            CHECK (trust_score BETWEEN 0 AND 1),
    total_reports       INTEGER NOT NULL DEFAULT 0,
    verified_reports    INTEGER NOT NULL DEFAULT 0,
    rejected_reports    INTEGER NOT NULL DEFAULT 0,
    last_seen_at        TIMESTAMPTZ,
    notes               TEXT,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3d. verification_log (FK → events)
CREATE TABLE verification_log (
    log_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    event_id        UUID NOT NULL REFERENCES events(event_id) ON DELETE CASCADE,
    action          TEXT NOT NULL
                        CHECK (action IN (
                            'verified','rejected','marked_suspicious','marked_duplicate'
                        )),
    performed_by    TEXT NOT NULL,
    notes           TEXT,
    performed_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- ============================================================
-- STEP 4: Indexes
-- ============================================================
CREATE INDEX idx_events_geom ON events USING GIST (geom);
CREATE INDEX idx_events_timestamp ON events (event_timestamp DESC);
CREATE INDEX idx_events_category ON events (event_category);
CREATE INDEX idx_events_verification_status ON events (verification_status);
CREATE INDEX idx_events_city ON events (city);
CREATE INDEX idx_events_cluster_id ON events (cluster_id);
CREATE INDEX idx_events_source_name ON events (source_name);
CREATE INDEX idx_events_source_id ON events (source_id);
CREATE INDEX idx_events_source_type ON events (source_type);
CREATE INDEX idx_clusters_centroid ON event_clusters USING GIST (centroid_geom);
CREATE INDEX idx_verification_log_event_id ON verification_log (event_id);

-- ============================================================
-- STEP 5: Triggers
-- ============================================================
CREATE TRIGGER trg_sync_geom
    BEFORE INSERT OR UPDATE OF latitude, longitude
    ON events
    FOR EACH ROW EXECUTE FUNCTION sync_geom();

CREATE TRIGGER trg_events_updated_at
    BEFORE UPDATE ON events
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();

CREATE TRIGGER trg_event_clusters_updated_at
    BEFORE UPDATE ON event_clusters
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();

CREATE TRIGGER trg_sources_updated_at
    BEFORE UPDATE ON sources
    FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

> **Deployment note:** This script is idempotent (`CREATE EXTENSION IF NOT EXISTS`).
> It is safe to re-run on an existing database.
